# Повторный аудит оптимизации

Дата: 2026-09-03

## Итог

Текущая архитектура компактна, циклов импортов нет, тяжёлая UI-библиотека удалена,
данные нормализуются один раз, список пагинируется, а изображения ниже первого ряда
загружаются лениво. Проверки проходят: 11 тестовых файлов, 37 тестов.

## Подтверждённые оптимизации

- Первый ряд изображений получает `eager/high`, остальные — `lazy/auto`.
- Размер первой страницы ограничен 4/6/8 карточками в зависимости от viewport.
- Нормализация внешнего массива выполняется один раз при создании `usePromotions()`.
- Для времени используется один `useNow()` на список, а не таймер на карточку.
- `ant-design-vue`, clipboard-пакеты и лишняя глубокая реактивность отсутствуют.
- Bonus IntersectionObserver останавливается после принятого показа и очищается при unmount.
- Новое click-событие содержит только `{name}`, без копирования URL, фильтров и UI-контекста.

## Актуальные точки улучшения

### P1 — обработчики на каждую карточку

Каждый экземпляр `Card.vue` создаёт собственные `window.scroll`, `onClickOutside` и
`matchMedia`-подписки. После «Показать ещё» их количество растёт вместе с DOM-карточками.
На текущих 31 записях это не критическая нагрузка, но это главный оставшийся источник
линейного роста глобальных обработчиков.

Рекомендация: вынести состояние открытого ERID-popover на уровень списка или создать
один общий scroll/outside-click coordinator. Выполнять отдельным UI-спринтом, поскольку
изменится управление фокусом и поведением нескольких popover.

### P1 — layout reads на каждом scroll

`useFixedNavigation.measure()` на каждом событии scroll вызывает два
`getBoundingClientRect()` и обновляет reactive state. Браузер может генерировать scroll
чаще одного раза за кадр.

Рекомендация: объединять измерения через `requestAnimationFrame`, сохранив текущий
автомат состояний и тесты `resolveNavigationState()`.

### P2 — повторяющиеся media query

`InfoActions`, `Tabs`, `useFixedNavigation` и каждая карточка независимо создают media
query listeners. Запрос hover одинаков для всех карточек.

Рекомендация: минимум — вычислять `canHover` один раз на уровне InfoActions и передавать
prop; более широкий viewport-context вводить только если появятся дополнительные
потребители.

### P2 — неограниченное ожидание host container

`hostReactAppReady()` повторяет `setTimeout` без максимального времени ожидания. Если
селектор хоста изменится или элемент останется нулевой высоты, цикл будет работать до
закрытия страницы и Vue-блок не смонтируется.

Рекомендация: добавить общий timeout и диагностическое завершение. Это прежде всего
исправление надёжности, но оно также исключает бесконечный polling.

### P3 — реальные Web Vitals не измерены

Статические проверки подтверждают атрибуты image priority, но не доказывают улучшение
LCP. Результат зависит от CMS, позиции секции, CDN и preload других ресурсов.

Рекомендация: сравнить LCP/CLS и waterfall на Coral/Sunmar стендах до дальнейших
изменений изображений. `srcset`/WebP добавлять только после подтверждения API CDN.

## Не рекомендуется сейчас

- Не объединять все composables: текущие границы ответственности читаемы.
- Не вводить глобальный store ради одного открытого popover без отдельного UI-спринта.
- Не заменять `@vueuse/core`: используемые функции покрывают очистку listeners и таймеров.
- Не оптимизировать 31 объект конфига на уровне алгоритмов — объём данных слишком мал,
  а основной потенциальный выигрыш находится в DOM, событиях и сетевой загрузке.
