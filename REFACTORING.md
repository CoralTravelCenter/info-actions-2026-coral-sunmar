# Рефакторинг `info-actions-2026`

Актуальное состояние на 2026-09-03. История исходного аудита и разбор бага
Яндекс.Метрики сохранены в `ANALYSIS-2026.md`.

## 1. Текущая архитектура

Поток данных остаётся однонаправленным:

```text
window._promotion_settings
  → getPromotions()
  → normalizePromotions()
  → usePromotions()
  → InfoActions.vue
  → Card.vue / Tabs.vue
```

Основные границы ответственности:

- `data/promotions.ts` синхронно читает внешний глобал;
- `data/promoSchema.ts` валидирует обязательные поля, санитизирует HTML и создаёт
  внутреннюю модель `Promotion`;
- `utils/configWarnings.ts` отделяет блокирующие UI-ошибки от неблокирующей диагностики;
- composables управляют фильтрацией, временем, пагинацией и контекстом аналитики;
- компоненты отвечают только за отображение и пользовательские события;
- `config/brand.ts` централизует бренд и отправку Bonus-показов;
- клики публикуются на `document` через DOM-событие `promotion-card:click`; его `detail`
  содержит только очищенное название акции `{name}`.
- Два простых обработчика в `external-scripts/` содержат отдельные `switch` для Coral и
  Sunmar и отправляют прежние коды `entry_point` в фиксированный счётчик своего бренда.

## 2. Выполнено

### Надёжность и аналитика

- Устранена гонка с загрузкой Яндекс.Метрики: цели буферизуются до появления счётчика.
- Бренд и номер счётчика определяются в одном модуле; неизвестный домен не отправляет
  аналитику в чужой счётчик.
- Bonus-показы дедуплицируются по ID акции, а не по DOM-узлу.
- Используются уникальные ключи карточек; переключение табов не пересоздаёт весь список.
- Клики передаются внешнему интеграционному слою через `promotion-card:click` только с
  полем `name`; технические данные карточки и UI-контекст наружу не публикуются.

### Контракт данных

- `name` и `visual` — обязательные поля; повреждённые записи изолируются.
- Канонический формат: `id`, `filters: string[]`, `legal`.
- Legacy `filter` и `ligal` временно поддерживаются и диагностируются.
- Проверяются календарная корректность дат, обратные диапазоны, HTTP(S)-URL,
  конфликтующие canonical/legacy-поля и тип `analytics.bonusImpression`.
- HTML из внешнего конфига экранируется; разрешён только `<br>`.
- Даты акций интерпретируются в `Europe/Moscow` и переоцениваются во время открытой сессии.

### UI, доступность и производительность

- Табы поддерживают клавиатуру и ARIA-семантику.
- Карточки используют `<article>`, корректный заголовок, `<time datetime>` и уникальные
  `aria-label` для действий.
- ERID-popover, копирование и предупреждение реализованы локально; `ant-design-vue` удалён.
- Первый визуальный ряд изображений получает `loading="eager"` и
  `fetchpriority="high"`: mobile — 1, tablet — 2, desktop Coral — 4, Sunmar — 3.
  Остальные изображения остаются ленивыми.
- В карточке удалены пять `!important`; повторяющиеся цвета переведены на CSS-токены.
- Есть адаптивная пагинация «Показать ещё» и фильтр «Скоро закончатся».

### Проверки

- Vitest покрывает даты, нормализацию, контрактные предупреждения, бренд, директиву
  показов, фильтрацию, пагинацию и fixed navigation.
- На 2026-09-03 проходят 9 тестовых файлов и 28 тестов.
- `vue-tsc` и `b2c-landing-vite check` проходят без ошибок.

## 3. Согласованные ограничения

- DEV-фикстура подключается обычным импортом в `scripts/info-actions.js` и вручную
  комментируется перед production-сборкой. Этот процесс оставлен по решению владельца.
- Внешний скрипт обязан записать `window._promotion_settings` до монтирования блока;
  поллинг и асинхронное ожидание не используются.
- JSON/CDN-источник, SSR и пререндер не вводятся.
- Доступность CDN-ресурсов по сети не проверяется валидатором.
- Legacy-поля нельзя удалить до миграции внешнего поставщика данных.
- Поле `entry_point` удалено из локальной фикстуры; три используемых значения перенесены
  во внешний скрипт Метрики.

## 4. Что осталось

### Обязательно перед production-релизом

1. Вручную отключить импорт `data/promotion-settings.js`.
2. Выполнить `npm run build` и `npm run check:production-config`.
3. На Coral/Sunmar стендах проверить фильтры, пагинацию, ERID, popup/link и responsive UI.
4. Проверить реальные цели `coral-bonus-show` и `sunmar-bonus-show` в счётчиках
   96674199 и 215233.
5. Измерить LCP/CLS и сетевой waterfall, чтобы подтвердить эффект image priority.

### Следующие самостоятельные задачи

1. Согласовать миграцию внешнего конфига на `id`, `filters` и `legal`; после переходного
   периода удалить legacy-адаптер отдельным изменением.
2. Рассмотреть `srcset`/WebP только после подтверждения API CDN.
3. Добавить ESLint/Prettier/Stylelint отдельным инфраструктурным спринтом, не смешивая
   его с функциональными изменениями.
4. Рассмотреть schema.org `ItemList` + `Offer`/`SaleEvent` отдельной SEO-задачей.
