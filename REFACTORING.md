# Рефакторинг `info-actions-2026`

Документ описывает **текущее состояние** блока «Акции» после рефакторинга 2026-08-11:
что сделано и почему, что сознательно пропущено, что осталось.

Исходный разбор проблем (версия 2025) и детальный разбор бага Яндекс.Метрики —
в `ANALYSIS-2026.md`. Инструкция по работе с конфигом — в `README.md`.

---

## 1. Главное: что чинили

Поводом был баг на продакшене — **цели Яндекс.Метрики не доходили**. Причина оказалась
в порядке операций внутри директивы показа:

```js
// было — ymbonus.directive.js
seen.add(el);                            // пометили как отправленное
if (typeof window.ym === 'function') {   // счётчика ещё нет → тихо ничего
  window.ym(counterId, 'reachGoal', goal, params);
}
stop();                                  // наблюдение выключено навсегда
```

Элемент помечался отправленным и observer останавливался **до** проверки готовности
счётчика. Карточки первого экрана пересекают вьюпорт сразу после монтирования — то есть
раньше, чем загрузится асинхронный `tag.js`. Ретрая нет, ошибки в консоли нет. Локально
счётчик успевал подняться из кэша, поэтому баг жил только на проде.

Вокруг этого вскрылся ещё пласт: три разных способа определения бренда (цели могли уйти
в чужой счётчик), дедупликация по DOM-элементу (показы задваивались при переключении
табов), неуникальные `:key` (в Метрику уезжало имя чужого баннера), пустой `entry_point`
у большинства акций (клики не считались вовсе).

## 2. Что сделано

### 2.1 Источник данных

| Изменение | Файл |
|---|---|
| `promotions.js` стал **загрузчиком**: на проде данные приходят из внешнего скрипта сайта в `window._promotion_settings`, в dev — из локальной фикстуры. Глобал читается синхронно, без поллинга. | `data/promotions.js` |
| **DEV-фикстура** (28 актуальных акций) подключается динамическим `import()` внутри `if (import.meta.env.DEV)`. При `build` Vite подставляет `false`, ветка вырезается — данных акций в прод-бандле нет. | `data/promotions.dev.js` |
| Точка входа больше **не пишет** в глобал, только читает. | `scripts/info-actions.js` |
| Компонент грузит данные асинхронно (`shallowRef` + `onMounted`), есть пустое состояние. | `InfoActions.vue` |

Проверка, что данные не попали в бандл:

```bash
npm run build
grep -c "PROMOTIONS_DEV\|coralbonus.ru/promo" '@CMS/info-actions.html'   # → 0
```

### 2.2 Яндекс.Метрика

| Изменение | Файл |
|---|---|
| **`brand.js`** — единый источник бренда и счётчика. Бренд определяется по домену второго уровня (`/(^\|\.)coral\.[a-z]+$/`), а не по подстроке `includes('coral')`, которая ложно срабатывала на посторонних хостах. | `config/brand.js` |
| **`reachGoal()` с буфером** — ключевой фикс. Не выходим молча при отсутствии `window.ym`: создаём совместимый со сниппетом буфер `ym.a`, и цели уезжают, как только счётчик поднимется. | `config/brand.js` |
| **`ymbonus`**: сначала отправка, потом пометка и `stop()`. Дедупликация переехала с `WeakSet` по DOM-узлу на `Set` по идентификатору акции и переживает переключение табов. | `directives/ymbonus.directive.js` |
| **`entry`**: при переходе в том же табе навигация ждёт callback Метрики (+ таймаут 300 мс) — иначе выгрузка страницы отменяла запрос. | `directives/entry.directive.js` |
| Во все директивы добавлен **`updated`** — без него при реюзе DOM-узла в Метрику уходило название предыдущей акции. | все три директивы |
| Единое соглашение по служебным полям: `Symbol('...Cleanup')` вместо `__ymStop` / `__entryCleanup__` / `__clipboardCleanup__`. | все три директивы |
| В dev каждый вызов логируется: `[metrika] reachGoal → ...`. | `config/brand.js` |

### 2.3 Контракт полей: обязательные и необязательные

Конфиг приходит из внешнего скрипта, поэтому граница «чужие данные → наш рендер»
описана явно интерфейсом `PromotionConfig` в `types/promotion.ts`; нормализация
выполняется в `data/promoSchema.ts`.

**Обязательные поля** (`REQUIRED_FIELDS`) — `name` и `visual`. Без них рисовать нечего:
запись отбрасывается и попадает в список `invalid`, о котором сообщаем в интерфейсе.
Это честнее, чем карточка с битой картинкой и пустым заголовком.

**Все остальные поля необязательные, и мы их не подменяем.** Нет `url` — рисуется кнопка
вместо ссылки. Нет `erid` — не рисуется плашка «Реклама». Нет `promo_end` — акция
бессрочная. Каждый такой случай уже обработан через `v-if` в шаблоне, поэтому
подставлять пустые строки не нужно.

Раньше нормализация делала именно это — «восстанавливала» отсутствующие поля:

```js
// было
entryPoint: String(p.entry_point ?? "").trim(),   // нет поля → "", и "" → ""
```

Проблема в том, что для `entry_point` отсутствие поля и пустая строка означают **разное**:
«трекинг не нужен» против «забыли заполнить». Подстановка склеивала эти случаи, и чтобы
их различить, приходилось потом заново перепроверять сырой массив. Лишний проход по
данным ради информации, которую сами же и потеряли.

Теперь `normalizePromotions()` добавляет только то, чего в конфиге нет и быть не может —
производные поля:

| Поле | Как считается | Зачем |
|---|---|---|
| `id` | `promo.id` → `name\|url` | уникальный `:key`; при дублях `name` Vue переиспользовал DOM и в Метрику уходило чужое название |
| `filtersArr` | `filter` (строка через запятую или массив) → массив | разбор один раз при загрузке, а не в `computed` на каждый ререндер |
| `isBonus` | `filtersArr.includes('CoralBonus')` | явная проверка вместо regex `/bonus/i` по строке |

Необязательные поля переносятся как есть — `undefined` остаётся `undefined`.

**Контракт `entry_point`** (цель `entry-point`, клик по «Подробнее») из трёх состояний:

| Значение | Поведение |
|---|---|
| поля нет в объекте | трекинг не нужен намеренно — тишина |
| `entry_point: ""` | ошибка контента → **уведомление в интерфейсе** |
| непустая строка | клик трекается |

Фолбэка на `name` намеренно нет: он маскировал бы недозаполненный конфиг и засорял
статистику непредсказуемыми значениями.

Проверки (`utils/configWarnings.js`) идут по сырым данным — там ещё видна разница между
отсутствующим и пустым полем, и различаются они через `in`:

```js
field in promo && String(promo[field] ?? "").trim() === ""
```

Уведомление — antd Notification в стиле предупреждения, одним списком на обе категории
проблем (отброшенные записи + пустой `entry_point`). Видно в dev всегда, на проде —
только по `?promo_debug=1`.

### 2.5 Даты

`filterFreshOffers` переведён на московское время: `dayjs.tz(value, 'YYYY-MM-DD HH:mm',
'Europe/Moscow')` + плагины `utc`/`timezone`. Раньше даты парсились в локальной зоне
пользователя, и акция «с 00:00 МСК» стартовала во Владивостоке на 7 часов раньше.
Сравнение идёт в абсолютном времени. Логика заодно упростилась до
`!start.isAfter(now) && !end.isBefore(now)`.

### 2.6 Замеры `ant-design-vue`

Проверили, тянется ли библиотека целиком — **нет**: именованные импорты тришейкаются,
в бандле нет `Table`/`DatePicker`/`Select`/`Modal`, из локалей только `en_US`. Основной
вес даёт общий рантайм antd (`Trigger`, `Wave`, `Empty`, cssinjs, tinycolor, vue-types,
ResizeObserver), который приезжает вместе с любым компонентом.

| Вариант | raw | gzip |
|---|---|---|
| Tooltip + Button (база) | 284 КБ | 98 КБ |
| + Alert | 298 КБ | 101 КБ |
| + **Notification** (текущий) | **327 КБ** | **110 КБ** |
| + Notification лениво | 334 КБ | 113 КБ |
| + ленивый `import('ant-design-vue')` | **1.5 МБ** | **462 КБ** |

Выводы, важные на будущее:
1. динамический `import('ant-design-vue')` **не тришейкается** — только конкретные пути
   вида `ant-design-vue/es/notification`;
2. ленивая загрузка здесь вредна: билдер инлайнит всё в один HTML, code splitting
   не работает, обвязка чанков добавляет 3–7 КБ;
3. Notification дороже Alert вдвое (+44 КБ против +14 КБ) — плата за то, что сообщение
   не занимает места в вёрстке.

## 3. Сознательно пропущено

| Что | Решение |
|---|---|
| Битые URL картинок с `%` | Не актуально — картинки отображаются корректно. |
| Опечатка `?banner_on_site = ` | Правится на стороне внешнего скрипта. |
| «Тикающее» время (`useNow`) | Лишнее усложнение. Реализована только таймзона МСК. |
| Конфиг JSON на CDN | Источником уже стал внешний скрипт сайта. |
| Clipboard поверх `copy-to-clipboard` / `useClipboard` | Свои директивы в приоритете, сторонние обёртки не тянем. |
| SSR / пререндер карточек | Невозможно. Взамен — оптимизация Vue и семантическая вёрстка; микроразметка отдельной задачей. |

## 4. Что осталось

1. **Проверить цели на стенде.** В dev каждый `reachGoal` пишется в консоль. Отдельно
   убедиться, что цели `coral-bonus-show`, `sunmar-bonus-show`, `entry-point` заведены
   в счётчиках 96674199 / 215233 — `reachGoal` на несуществующую цель молчит.
2. **Валидатор конфига** под `import.meta.env.DEV`: уникальность `id`, парсибельность дат,
   `promo_start < promo_end`, наличие `erid` при `legal`. Данные приходят извне —
   это единственный способ поймать поломку контракта.
3. **Согласовать формат записей** с владельцем внешнего скрипта: `ligal` → `legal`,
   `filter` → массив вместо строки с запятыми, уникальный `id`, заполненный `entry_point`.
4. **Перф загрузки**: первым 2–4 карточкам `loading="eager"` + `fetchpriority="high"`
   (сейчас `lazy` у всех, включая первый экран → страдает LCP), `srcset`/`webp` от CDN.
5. **Убрать `ant-design-vue`** — самая дорогая зависимость ради тултипа, кнопки и
   уведомления. По принципу «свои директивы в приоритете» логичен свой поповер
   на `@floating-ui/dom`.
6. **Стили**: `!important` ×5 в `Card.scss`, хардкод цветов → CSS-переменные,
   `respond-up` вместо дублей `@media (width >= 1280px)`.
7. **Тесты и линтеры**: Vitest на `filterFreshOffers` (граничные даты + проверка, что
   результат одинаков при `TZ=Asia/Vladivostok` и `TZ=Europe/Kaliningrad`),
   ESLint/Prettier/Stylelint, `jsconfig.json` + JSDoc-типизация.
8. **Микроразметка** `ItemList` + `Offer`/`SaleEvent` — почва подготовлена семантическими
   `<article>` и `<time datetime>`.

## 5. Структура после рефакторинга

```
src/
  config/brand.js              — BRAND + METRIKA + reachGoal (единый источник правды)
  data/
    promoSchema.ts             — проверка обязательных полей + нормализация
    promotions.ts              — типизированный загрузчик: глобал на проде, фикстура в dev
    promotions.dev.js          — DEV-фикстура, в прод-бандл не попадает
  directives/
    ymbonus.directive.js       — цель показа (дедуп по id акции)
    entry.directive.js         — цель клика (гарантия доставки перед переходом)
    clipboard.directive.js     — копирование erid, своя реализация
  utils/
    filterFreshOffers.js       — актуальность по датам, МСК
    configWarnings.js          — проверки конфига (нет обязательных полей, пустой entry_point)
  types/
    promotion.ts               — PromotionConfig и готовая к рендеру Promotion
  components/InfoActions/
    InfoActions.vue            — загрузка, фильтрация, уведомление о проблемах конфига
    Card/Card.vue + Card.scss  — карточка акции
    Tabs/Tabs.vue + Tabs.scss  — фильтры (role="tablist")
```
